# 界面设计说明

2026-11-19，第四轮。这一轮把工作台改成一块画布：设计的每一步都是画布上的一张卡片，在卡片上直接做，右侧面板跟着所选的那一步变化。下面说明为什么这样改、每一步长什么样、依据是什么，以及还没有验证的地方。

## 一、上一版的问题

上一版有四个页面：画布、目标、参数、候选图。画布上只有两张展示用的卡片，不能在上面加步骤；写目标、调参数、生成都要离开画布去另一个页面，做完之后画布才把结果画成一张关系图。作者试用后的判断是：这反直觉，步骤被拆散了，画布只是事后的流程图；同时流程被排成固定的顺序，设计显得僵硬。

## 二、依据

[画布式工作流拆解](../../planning/workbench-handoff/literature/画布式工作流拆解.md)读了三项把同一后端接到不同界面上比较的研究，结论可以直接用：

- 步骤应当是画布上的对象。设计者选中一个对象、点一个直接动作，系统把新对象接在后面并自动连线。在 Workflow-Net 的九人比较里，这种做法的创造力支持、可用性和负荷三项都好于手工接线的节点图和只靠对话的界面；手工接线把人锁在一条线上，对话到细化阶段失控。
- 节点里可以直接干活。DesignTrace 的每个节点内嵌一块可编辑的画布，并保存自己的历史。
- 参数放在随所选节点变化的侧栏里。InspirationGraph 有意不像 ComfyUI 那样把参数塞进节点，以保持画布清楚。
- 对话适合开头的发散，不能是唯一入口；过程历史要自动留下，不要让设计者手工维护。

作者设想的布局是“画布，加右侧的组件面板或对话界面，随每一步变化”。这与上面几条一致。

## 三、一块画布

```
┌ 顶栏：我的项目 / B2 案例 · 撤销 · 显示留档 · 研究详情与导出 ─────────────┐
│                                                        │ 右侧面板          │
│  [依据]─▶[目标]─▶[造型]─▶[生成]─▶[候选图]─▶[取舍]        │ 这一步 | 设计对话  │
│                    │                 └─▶[生成]─▶[候选图] │                   │
│          [目标]─▶[造型]（另一个方向）    [参考图] [便签]   │ 随所选卡片变化     │
│                                                        │                   │
│        底部工具条：目标 · 参考图 · 便签 · 新方向 · 生成效果图               │
└────────────────────────────────────────────────────────────────────────┘
```

**卡片就是步骤，在卡片上直接做。**

| 卡片 | 在卡片上能做什么 | 选中后右侧面板给出 | 对应论文 |
| --- | --- | --- | --- |
| 目标 | 直接写一句想要的变化，回车保存 | 按话题和使用状态查到的用户原话，采用、驳回或只存自定目标；用途与构型；外观偏好词对；全部公开短引的检索 | 3.2 需求资料，3.3.1 意图与词对 |
| 用户依据 | 一张公开短引，连着它支持的目标 | 原话、对象、适用限制、来源编号 | 3.2 |
| 造型 | 顶视图就在卡片里：拖橙色轴心改轴距和横纵比，点机身或桨盘出现可拖的手柄；切换顶视、条件图、侧视；下方是三个比例读数 | 五个部件页签的参数；布局空间图、设计提示、参考机型；撤销与叠加层开关 | 3.4 参数与条件图，4.1.2 部件 |
| 参考图 | 上传、拖入，或从 B2 案例引用 | 以此图生成、对照、移除 | 3.5.1 条件输入 |
| 生成 | 待提交时是虚线卡片，点卡片上的「生成」才提交 | 将要提交的三样内容：布局条件图、由造型和目标编译的文字、参考图；这一轮想改变什么 | 3.3.3 人工确认，3.5.1 |
| 候选图 | 回图自动接在那一轮后面 | 保留、以此图继续生成、图片对照；驳回与回选在完整记录里 | 4.2 方案比较与取舍 |
| 取舍、便签 | 取舍自动留下；便签随手写 | 来源与关系 | 4.2 |

**怎样加一步。** 四种方式做同一件事，都不需要手工接线：

1. 选中一张卡片，它上方出现接下来能做的事。造型卡片给出「生成效果图」「另开方向」「存为版本」，候选图给出「保留」「以此图继续」「对照」，参考图给出「以此图生成」。点一下，新卡片出现在它右边并连好线。
2. 底部工具条：目标、参考图、便签、新方向、生成效果图。
3. 双击画布空白处，在那个位置添加便签、参考图、新方向或生成步骤；把图片文件直接拖进画布就是一张参考图。
4. 从卡片右侧的加号拖一条线到另一张卡片。把图拖到「生成」卡片上，这张图就随那一轮提交；拖到其他卡片上，记为设计上的参考关系。

**右侧面板随所选步骤变化。** 没有选中任何卡片时，面板列出目标、造型、生成、取舍四项的进度，并标出下一步；这是按规则算出的提示，没有调用模型。面板的另一个页签是设计对话，围绕当前方向和正在看的部件：只查依据不需要模型账号，查到的原句可以放到画布上；模型给出的机身宽度建议先在造型卡片上以虚线预览，由设计者决定应用、驳回或撤销。

**放上去的也能拿下来。** 选中便签、参考图或待提交的生成步骤，按 Delete 或点「移除」；设计者自己放上画布的证据卡可以「从画布移开」，随目标采纳的依据要在目标面板里撤销。已经提交的生成轮次、候选图和取舍是记录，不能删除。

**不规定顺序。** 可以先写目标，也可以先拖造型、先放一张参考图。几个方向并排在画布上，点哪个方向的卡片就编辑哪个；每个方向有自己的目标、造型和生成记录。造型项（臂根、材料、机身轮廓、顶盖、相机安装、主色、表面）仍然可以不指定，不指定就不写进提交的文字。

**卡片不乱跑。** 第一次打开时按来源关系排成列：依据 → 目标 → 造型 → 生成 → 候选 → 取舍。之后每张新卡片只在出现时安放一次（接在来源右边，新方向排在原方向正下方），已有的卡片和设计者拖过的位置都不动。左下角的「整理」可以按来源关系重排全部卡片。

## 四、研究记录放在哪里

设计者的主线上只有上表这些卡片。每一轮冻结的规格和布局条件图是研究留档，默认收起；点顶栏的「显示留档」在同一块画布上展开，连线标注冻结输入和实际使用的父图。「研究详情与导出」是画布之外唯一的一层，放逐句的提示词来源、规格卡、导出、全部轮次的回执与取舍、历史回放和旧版 ComfyUI 回执导入。这样做是按[双机交接](../../planning/workbench-handoff/README.md)里的要求：减少主流程的操作负担，把来源、图像输入、规格版本与模型回执放在可展开的研究详情里，同时保留可查的原句、父图、采纳、驳回和撤销。

每一轮生成仍然记录实际提交的文字、条件图摘要、父图或参考图、服务回执和候选原图摘要。新加的一种输入是画布上的参考图：提交的文字用单独一句说明“第二张图是设计者选的外观参考”，记录里的父图编号指向画布上那张参考图；上传的 JPEG 或 WebP 在浏览器里转成 PNG 再提交。

## 五、保留下来的设计

- 轴心几何、条件图、坐标和提示词布局句仍出自同一组数（`computeLayout`）。
- 四个比例读数旁标出真实机型的范围；设计提示仍是相机视野、桨盘重叠、桨与机身间隙三条俯视近似。
- 目标用语义检索找原话：按使用任务、构型、话题和观察状态筛选，场景不符时可以只存自定目标，驳回要写理由。
- 每一步都能撤销；改过的参数可单独重置；保存的版本不可变，可以从任一版本继续。
- 换了使用任务或构型族时，已确认的目标仍需重新确认。原来的文字留在目标卡片上作为未保存的草稿，按一下「确认目标」即可，不会凭空消失。
- 视觉上仍是浅色点阵画布、白色卡片、墨绿作强调、信号橙只用于电机轴心。

## 六、窄屏

宽度小于 900 像素时，面板移到画布下方，画布随之缩小并把选中的卡片缩到看得见；底部工具条只留图标。手机上可以查看和做简单修改，拖动造型建议在平板或桌面上做。

## 七、还没有验证的

- 这一轮只做了软件走查：`npm run walkthrough:canvas` 在隔离的浏览器里把上面每一步都做了一遍，图像作业由软件夹具应答。没有调用模型，没有作者试用，也没有外部设计者参与。界面是否更直觉、是否更省时，要由作者预试和配对试验回答。
- 文献支持的是“步骤放在画布上、直接操作、自动连线、侧栏随所选对象变化”这一选择；原研究的任务是椅子、灯具、杯子一类，各九人。不能据此预设在多旋翼任务上的效果。
- 参考图作为生成输入没有对真实模型测过。
- 这套步骤换一种产品时，需要替换的是评论语料与话题标注、参数与几何规则、提示词编译三样数据。这是结构上的判断，没有在第二种产品上试过。
- 没有做的：在画布上直接圈选候选图的局部再改；多张候选的批量比较；按相邻夹角输入布局；折叠状态。
