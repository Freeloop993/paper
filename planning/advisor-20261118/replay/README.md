## 给系统实现的验收条件

1. 同一任务 ID 下持久化设计者简报、构型及视图、意图作用范围、规格快照、条件图、编译原词、设计者改词及实际请求。每件文件可按版本和摘要重新定位。将“模型生成”“人工拼合”“既有历史导入”区分为不同操作来源。
2. 原任务发出后记录真实回执、全部候选、实际等待和操作时间。每次选图、弃用、更换父图或引用辅助图分别登记行为主体、理由及时间。四旋原评表当时父图为空、后来确认 B2，系统须能保留两次不同状态。
3. 六旋例的旧请求和更正请求同时保留，更正后才产生的新图单列。设计者回退、协议更正、模型重新生成三种操作能单独查询。缺真人决定或计时，报为“未采集”。
4. 导入两例并对上上述摘要后，再用新系统各走一遍结构化与自由提示的真实作者预试。历史档案的回放次数、自动化点击和真人正式场次分别计数。E4 双条件比较须复用一致的后端和记录口径。[PR #75 能力核对](https://github.com/lucienzhu/paper/blob/d6dfb211343bb8ee0b7a2b4f75f976ce7b1d16b2/prototypes/drone-configurator/review/20261118-round3/thesis-alignment.md) · [E4 研究工单](https://github.com/Freeloop993/paper/issues/23)

## 如何复验

用 Python 3 和 Pillow（本轮实跑无 GPU、无网络）。在固定提交 e96d419 的原始文件上运行；独立判读 JSON 另取 9afe690。建议使用原始 Git blob 字节，自动转换 CRLF 的工作区可影响登记时的 SHA-256。文件分开存放时可用 --guides、--hexa-freeze、--archives、--manual-images 指明其目录。

```text
python -B check_design_records.py <e96d419项目根目录> --independent-read <9afe690的six-unblinded.json> --out replay.json
```

程序先核验实发与登记、回执、采样、正向任务及输入哈希，再复算两个补充环节。人工拼合中，去窗图相对原 B2 改动 1,305 个像素，上／下端安装图相对同一去窗图分别改动 3,286／3,114 个像素。六旋独立判读按六点水平跨度和垂直跨度复算归一化 q。源数据异常即报错；本次额外检查了错配条件图、回执 ID 和改写一个请求字节三个控制样例，三项分别被拒绝。以上检查重放历史输入和记录，未重跑模型，未推断模型可按种子产生相同像素。
