# Claude 的设计系统实施规格

基于 [PR #75 的第三轮界面](https://github.com/lucienzhu/paper/tree/d6dfb211343bb8ee0b7a2b4f75f976ce7b1d16b2/prototypes/drone-configurator)。保留洞察、造型、交付三段和方案对比画布。开发的第一份交付应支持设计者从一句任务意图走到一次有据可查的取舍。

## 后台整理语义，前台填写简报

后台索引以工作版本发布。每条记录包含来源编号、任务/产品类别、原句涉及的对象与状态、设计语义、人工编码理由、冲突或缺失、可公开级别。参数另表保存，注明已有量测、待检验假设、设计者选择三种来源。连接两表时保留关系的提出者与版本。受试界面只展示可公开的短依据。

设计者先选择使用任务、构型和要设计的外观，再输入或勾选意图。系统在后台按任务、状态、部位和已有词典检索，把建议放在相应设计动作旁。每条建议可查看证据、采纳、驳回或自行定义；预览变更、确认再写入规格卡。保存人工选择与来源。语料总量、主题统计和完整卡片检索放入研究资料入口。

| 给系统的输入 | 可见行为与验收 |
|---|---|
| “折起来放进小包” | 先识别折叠和收纳状态。索引能返回相应依据。仅有展开顶视图时提示当前观察边界；设计者可以保留此需求供折叠表达使用。 |
| “展开时希望机身显得紧凑” | 识别展开状态和外观感知。候选给出机身宽度与布局跨度、机身长宽比等代理量、原始定义和证据等级。设计者可调整或拒绝。数值与感受的关系由独立评议检验。 |
| 单写“小巧”，未给状态 | 展示“展开外观 / 折叠收纳 / 其他”让设计者澄清，或记为尚未指定位相；未经确认保持现有值。 |
| 农业植保任务搜到消费航拍评论 | 默认按任务过滤。跨任务材料如作类比，显式标明来源和局限。没有合适材料时允许自定。 |
| 更改或撤销某一建议 | 展示将改变的字段和保持项，导出记录保留之前的值、来源和设计者的决定。 |

先用规则与结构化索引实现可回放的基线。评估 RAG 时冻结同一证据库和独立人工标注查询集，包含同义、状态歧义、跨任务、无答案与反例。比较规则、字段检索和候选 RAG 的相关证据命中、错误任务率、无依据建议率、无答案时能否克制、耗时。记录每条查询的前三项及漏检。相同模型与生成预算另测意图与外观是否被独立读出。选型依据是各项实测收益与代价。

统计主题必须标明分母、字段与数据集版本。PR #75 中护圈标签写为 0，本次对 228 簇复算发现，“护罩构型与桨叶表达”有 2 簇，“防护安心感知”有 3 簇，两类去重合计 4 簇；这些标签含义不同。缺少“护圈”专门编码的地方标记为未统计。对同源正、反例保留共同来源标记，切勿把 36 张展示卡当作 228 簇的频率分布。

同一语义可以跨构型检索，各构型分别登记可编辑部件、适用方向和依据。缺少对应时保留原始意图，让设计者自定。在两种构型上各走一次同词任务，检查系统取回哪条依据、实际改了哪个部件、设计者接受或拒绝的理由；读者能否从图中识别目标意象另测。这与相关的按品类建立语义编辑和保留原拓扑的方法相呼应。[方法原页与适用范围](literature/followup.md)

知识检索是否改进系统需要分两次验。先评返回资料与设计任务的关系，再由独立读者评生成外观。已有概念评估研究发现，加入检索知识改变了模型打分，但模型与专家的一致程度并未提高。本项目对“紧凑感”的评议保留真人读数。[Mas’udah 等，DESIGN 2026](https://doi.org/10.1017/pds.2026.10603)

## 一份规格驱动所有输出

把“任务”与“布局”分开。布局至少区分可见轴位、每个轴位的层数、预期旋翼总数、观察视图和朝向。尺度定义按构型记录。正视顶图与斜视有各自的观察量；只有明确属于同一方案的补充视图才能用来判读层级。对既有四旋保留原有尺度、参数和旧 JSON 导入行为。六旋历史资料中的归一化比例与本版画布显示的宽长比须分别标识。三旋没有成对的对置轴位，界面必须给出适用的尺度定义或将原指标标为不适用。

| 正常操作 | 通过证据 |
|---|---|
| 选择任务和构型，导出当前方案 | 在简报、画布、条件图、提示词、规格 JSON、实际提交六处核对同一个构型和任务。换成六旋后逐句检查提示词及附加词，保留历史错误输入供复核。 |
| 给同一布局切换视图 | 显示此视图可以判读的对象和不可见项。共轴示意图允许表示上下层；生成顶图的根数与层数分别记为读数与未知。 |
| 选一个参数并要求其他部位保持 | 提交前保存“想改什么、想保住什么、自由项”。输出阶段分别记录目标达成、非目标保持和不可判。 |
| 复读旧规格及真实历史输出 | 原始规格/请求/图像使用原件摘要；导入要保留输入版本。把回放、真实作者预试、正式设计者会话区分开。 |

## 从候选回到下一次设计决定

**已复现的输入故障。** 在 Node 24.13.0 读取第三轮导出的第一份真 X 规格，经生产代码 `parseImported` 和 `buildExport` 重新编译，四旋显示 4 个轴位。仅将底层机架选项改成 `Radial Hex`，导出得到 6 个轴位与一条六轴布局句，但首句仍要求生成四旋，任务标签仍写日常随行航拍四旋翼。普通机架选择器还未暴露这项六旋选项。两次导出均显示模型停用、父图为空。此探针对输入侧的真实导出函数运行，未执行生图。后继版本应从正常入口复测这两个任务及其实际出图回执。

复用[旧 C1 会话与主持人回执逻辑](https://github.com/Freeloop993/paper/tree/31b3730a183000fed01abb42a61b605a7a6fa6b6/prototypes/e4-author-pilot)。一次尝试允许一组候选，模型可外置，由主持人按实际结果回填。保留原始编译文字、设计者确认后的文字、实际发送的文字和差异；关联条件图、模型版本、种子或服务实际提供的标识、提交与返回时间、回执、输出摘要。失败和重试单独保留，同一尝试重复导入相同回执应可识别。

设计者可以保留、拒绝、回退、人工深化或终止。保存所选候选编号、父版本和理由。若人工接手，用单独的修改记录标明来源，支持回看所有落选候选。系统可记录意图转译过程中 AI 助手的参与，最后由设计者确认规格。结构化与自由提示使用同后端、同任务资源上限及同一套计时。主动操作、等待模型、人工交接分别累计。导出包能逐尝试复核，不向盲评者展示条件、操作日志或参考答案。

复现方式（退出码 1 表示至少有一项不一致）。工具通过已归档的新版导出调用原版输入函数，只测构型、任务标签与首句的一致性。未来界面可自由修改交互，正式验收仍要核对真实设计任务与全部导出件。

```text
node probe-layout.mjs <PR75配置器源码目录> --check
```

## 放行次序

研究侧已有[PR #75 输入与真实回执桥接工具](pilot-bridge/README.md)和[正常浏览器入口复核](pilot/README.md)。后继界面应沿用其原件摘要、版本与缺失值定义，公平比较两种方式。对 E4 冻结同一检索政策，RAG 增益另作离线或独立对照。检索评估按评论来源及近重复分组划分开发与保留集，避免同源卡同时进入两侧。

1. 在 PR #75 后继提交上记录版本，用正常界面回放真实四旋案例，并用六旋案例逐项检查图与文字。保留所有不一致和不可重建项。
2. 在固定查询集上核对两种紧凑语义、跨任务和空结果；对照系统实际保存的条件图和实际输入，不以界面自报代替。
3. 作者完成两场真实预试。分别提交、等待回图、选案或回退并导出记录。若两种条件资源不同或计时无法分段，修正并记一次协议改动。
4. 作者确认预试流程后冻结系统、简报和评分方法，才启动正式配对和新构型批次。渲染示意、浏览器脚本、历史回放、新生成与真人数据分别登记。
