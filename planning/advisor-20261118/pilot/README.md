# C2 双条件真实预试开场与验收

**主持人实施入口。** [新版导出接真实回执的研究侧工具](../pilot-bridge/README.md)可保存两种条件的尝试、原图、分段时间、取舍与回退。下文是 PR #75 和旧 C1 两个原界面的现场复核；浏览器里的原导入仍有版本差异。进入作者场次前，须先在统一的后继界面验收任务与构型，并确认真实后端的操作安排。

2026-11-18。适用于作者、实验主持人与系统维护者。当前作者真实双场尚待举行。旧 C1 支持主持人接入外部模型，PR #75 的新版配置器已做到交付设计输入。**在新版正常入口完成一对可追溯的真实设计场次，仍需要接通两个环节。**

| 项目 | 在浏览器与源码中核实的情况 | 对 C2 的影响 |

## 维护者在新版先做的一次联调

1. 从当前正常配置器入口出发，使用一份冻结 S 任务和一份 D 任务。S 导出已确认文字与布局图；D 实发作者原文。两份任务使用相同后端版本、画幅、机会与总候选上限。两组都可看到简报的共同参照，模型实际收到的材料逐组登记。两组的差异是整套交互和输入方式，解释对照结果时不能单独归因给布局图、界面或知识检索。
2. 每次使用稳定机会编号关联冻结规格/原文、实发原件、全部回执、候选原图及摘要。一个机会多次调用、一次调用多张、请求失败、无图、等待中刷新、旧候选回选都保留实际对应关系。分别显示机会数、执行的调用数、回件图数、可供选择图数，避免 9 次机会与 9 张图混计。
3. 在隔离软件演练中核对故障及缺失字段，随后用同一个候选在盲态材料中重定位。主持人的交接、候选首次可见和作者做出决定分别记录。修改前后的流程指向不同提交，并随包保留当时的协议。
4. 顶视六旋从正常界面选择农业任务后，规格、条件图、槽位与实际输入均明确六旋；指向旧四旋航拍的文字或引用须明确处理。另用 B2、六旋历史数据复核原件，历史、软件试跑和新作者会话分开登记。

| 时点 | 作者要做的事 | 主持人留存 |
|---|---|---|

## 导出检查

历史 C1 当前格式可运行以下命令。工具本地读入成对导出，输出仅含会话条件、计数、缺失项及结构问题。通过结构检查还需要到外部后端逐次核对原件和设计者的真实参与。新版扩展多候选时要为新格式补相应检查。

```text
python audit-pair.py <本地成对导出.json>
```

重放浏览器检查可设置 `PLAYWRIGHT_CORE` 指向 Playwright Core，`BROWSER_CHANNEL=chrome`，使用 Node、Python 3 以及两份解压后的离线包。

```text
node browser-compat.cjs <PR75离线目录> <C1归档离线目录> observations.json
```

[导出检查脚本](audit-pair.py)会检验 S/D 与分配、提示词摘要、成功返回 PNG 的摘要、候选选择指向、主动/等待/暂停时长和、回执缺失与后端偏离。浏览器测试中，完整模拟包的结构通过；检测到 10 处外部字段缺失；另一个篡改提示词的测试包触发校验失败。
