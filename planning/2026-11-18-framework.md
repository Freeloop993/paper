## 一、一页结论

**题目要证明的事。** 设计者能把用户语义和工程比例写成一份可编辑的规格，生成结果在这些参数上可量测、可判读，设计者在有边界的修订中掌握取舍，最终方案能被不知情的人读出设计意图；与自由提示相比，这套做法有可量化的收益或代价。

### 2.2 贡献（正面写，三条）

先说清楚**不能**作为创新的部分。文献检索（[文献补充](../references/2026-11-18-literature-additions.md)，已抽查）找到了几项与本文很近的工作：

| 已有工作 | 已经做到的 | 本文因此不能声称 |
|---|---|---|
| AutoGen-Insight（Wang 等，2026） | 评论 → 可检视的比例与造型参数向量 → 参数化提示词 → 扩散生成，与 LLM 提示基线比较 | 首次把用户评论转为参数规格再生成 |
| Parametric-ControlNet（Zhou 等，JMD 2025） | 参数与部件图驱动的可控扩散生成，并从生成图回归参数量测依从 | 首次实现产品造型的参数化可控生成 |
| Chen 等（2026，已引）；Yamin 与 Cauchard（2022） | 评论驱动的无人机概念生成；生成式无人机外观加喜爱度评价 | 首次把生成式 AI 用于无人机造型 |
| Davis 等（CHI 2024）、DesignWeaver（CHI 2025）、Brief2Design（2026） | 结构化或图形化界面与自由文本提示的对照，样本 12—52 人 | 结构化提示优于自由提示（本文 3 人只能作形成性验证） |
| PIE-Bench、EditBench、InstructPix2Pix、MagicBrush | 编辑达成与非编辑区保持分开评价 | 分开评价本身 |

以下三项是拟报告的贡献及当前验证边界。

1. **方法：免训练、由配置器编译的双重参数规格。** 用户语义与工程比例写在同一份规格里，配置器把它编译成条件图与固定短语，不训练模型；每张图可追溯到规格、输入与种子；设计者在有边界的修订中保留、回退或接手。与 Parametric-ControlNet 相比不需训练、几何量直接从图上量；与 AutoGen-Insight 相比几何不经文字传达。
2. **两种生成通路的比例响应。** 在已登记的档位与容差下，部件图路线的两项比例各命中 12/12。实际设计使用的点线图路线在较窄目标档出现向宽偏移。与真实产品样本的关系须用独立取点、扩大后的样本及新的档位对照验证。
3. **部件级评价与设计证据。** 分别判读臂根、机鼻、顶盖分件的目标达成、非目标保持和可见性。已有 B2 的作者取舍与人工深化记录。计划由三名外部设计者完成两种方式的配对，当前正式完成 0 对。

第 3 条的后半部分取决于 E4 与 D1 是否完成；若 E4 结果是“没有差别”，同样可以写。第二章 2.6 节用一张逐维度比较表（输入、控制方式、评价、人的角色）把上表的五项工作与本文并列。

### 2.4 “紧凑”是语义与工程接上的地方

- 评论里最主要的诉求是小巧（228 条中 43%）、便携（29%）、轻（21%）；第二编码中“紧凑—舒展”的一致性也最高（κ＝0.60）。
- 8 款实拍的紧凑感评分有明显差别：Neo、Neo 2 中位 2（偏紧凑），Air 3 中位 6（偏舒展）。这说明紧凑感读得出来，而且随产品变化。
- 已量到的 3 款中，机身宽与对角轴距之比（PV02）Neo 0.234、Mavic 3 Pro 0.211、Air 3 0.208，方向与紧凑感评分一致，但 3 个点不能下结论。
- 文献上，Mugge 等（2018）从 120 件耐用品中得出的五个外观感知维度里就有“紧凑”；Raghubir 与 Krishna（1999）发现伸长方向影响体积知觉，可作为 W/L 与“小巧”关系的假设来源（对象是容器，引用时要加限定）。

所以“紧凑”有可能用比例参数表达：机身宽与对角轴距之比、机身长宽比、d/D。检验分两步：真实产品上看比例与紧凑感评分是否相关（S5 第一步，需要更多机型与评议者）；生成图上只改比例，看评议者是否觉得更紧凑（S5 第二步）。【待议 Q1：是否把“紧凑”恢复为首要语义目标】
