## 作者与导师确定的范围

项目是工业设计工程毕业论文《人智协同驱动的多旋翼无人机造型参数化可控生成方法研究》。第四章采用《四旋翼无人机的人智协同设计》，主任务是日常随行航拍，重点看相机与机身的整合、机臂与机身的过渡，以及设计者怎样在候选之间取舍。第五章采用《关键设计指标验证与跨构型无人机设计应用》，需要说明同一方法换构型后有哪些环节可以复用，以及控制在什么条件下失效。先让系统、预试和评议材料能真正运行，再写实证章节。[研究范围和历史变更](https://github.com/Freeloop993/paper/blob/a98b3ecdce0330902d9f5dd99336ce41e7fc993e/docs/requirements.md) · [研究任务与验收](../../advisor-20261118/README.md)

导师批注稿目录其余四章依次为第一章《绪论》、第二章《相关研究与理论基础》、第三章《造型意图转译与人智协同可控生成方法》和第六章《结论与展望》。

| 研究问题 | 工作台要让设计者完成的事 | 用什么回答 |
|---|---|---|
| RQ1 用户说的「紧凑」具体指什么？ | 从原话确认部件、状态与场景，区分折叠收纳、展开外观和主观携带感。设计者能看卡片原话、反例和适用限制，也能登记自己的假设 | 用按来源隔离的标注题评估检索命中、错场景引用、应当澄清或拒答的题；另用匿名实际回图请独立观察者评议视觉意象 |
| RQ2 哪些布局比例和部件特征可控？ | 选定可编辑的局部目标，预览改动，保存要保持的其他特征和实际送入模型的条件 | 量测目标与输出的误差、局部修改达成和非目标部位保持。逐张记录可判性、不可判原因和所用视图 |
| RQ3 人与 AI 怎样分工，结构化方式带来哪些收益和代价？ | 对话提出可以检查的修改，设计者采纳、驳回、撤销或人工深化；实际回图、父图、取舍理由要能找回 | 先做四旋作者双条件预试，再按同一协议进行外部设计者配对操作。分别记录主动时间、等待、提交、回图、取舍和终稿评议 |
| RQ4 换构型后，哪些环节仍可复用？ | 区分使用任务与旋翼构型。保存顶视可见轴位、每轴层数和构型适用的尺度 | 先用同一中性展开任务比较四旋与平面六旋，再按证据和资源扩展三旋、平面八旋与共轴。共轴下层需要同一方案关联的补充观察 |

四旋 B2 已有人工深化与作者倾向的档案；农业六旋已有另一项真实任务下的 39 张更正输出，其中 36 张有独立 AI 布局复测。两组可以回放。要估计构型差异，需在中性任务中重新对齐视角、模型、条件图和预算。不能用以往农业与日常航拍之间的差异代替这项比较。[四旋 B2 档案](https://github.com/Freeloop993/paper/tree/e96d41946ea84237da506bb76c2f713a3f3b9275/experiments/e3-deepening) · [跨构型试验协议](../../advisor-20261118/cross-layout-protocol.md)

## 前端下一轮要解决什么

作者明确希望画布上的图与图具有可读的来源关系。设计者知道「现在要定什么、点哪里、怎样得到图、如何继续修改」即可开始工作。对提示词、后台回执和实验记录的核查放进可展开的研究详情。作者已看过目前版本，仍对整体体验不满意；现有截图用于识别已经做过的操作，视觉风格与布局仍可重做。

- **目标。** 日常用语从「设计目标」进入；「生成时想改变什么」可以补充。语义材料随当前部件和任务出现。本地 36 张脱敏短引来自 35 个匿名来源、涉及 17 个话题，另有 228 个造型表述簇用于主题统计。界面应分别显示命中卡数、来源数和回答实际引用的卡。消费航拍的折叠例证不能推出农业六旋的造型要求。
- **画布。** 让设计者看出当前草稿、冻结版本、输入图、候选、父图和人工修改之间的关系。人与界面手动连出的参考线、真正送往后端的输入，以及回执确认的输出，在研究记录中含义不同。B2 案例可用于检查读图顺序。
- **改形。** 参数控件直接操作；设计对话的尺寸建议显示改前、改后和适用部件。当前可执行聊天试调为机身宽度。预览期间保留原值，应用后才更新；驳回可写理由，撤销能恢复上一次人工值。换方案、换上下文、切页及慢回复返回之后仍应对应发起时的方案。
- **生图。** 正常入口从设计目标与当前草稿直接生成并收回候选。设计者可以用选中的候选继续生成。高级研究入口可查实际提示、图和回执。H3 的托管图像编辑和 Qwen/ComfyUI 的工作流使用不同的服务证据，试验比较时要登记实际后端、两组可见的材料、传给后端的图以及预算。
- **取舍。** 记录候选真正展示、选择、驳回、回选、人工深化及操作理由。冻结上一轮，不让新参数覆盖旧案；删除一个方案并复用显示字母后，新方案不应带入旧父图。
- **另一台电脑。** 普通 Git 克隆包含检查代码、离线资产和本包示例。浏览器草稿与轮次原件分别存于浏览器存储及本机服务，因设备和站点来源而异。使用者先在第一台导出需要保全的真实轮次和规格；第二台可导入工作台支持的规格并查看已提交的脱敏示例。本包没有承诺整份轮次 JSON 可自动恢复为可编辑工作区。在线模型需在目标机器的本地服务中单独提供凭据。

## 接下来的实验顺序

1. 冻结要评估的界面和词典版本。用常规入口核查四旋的「折叠装包」「展开显得紧凑」「无关问题」和农业场景，检查本地返回、模型实际引用与越界建议。核对六旋输出的目标、规格、提示和条件图能相互对应。
2. 先跑作者双条件预试。两份既有任务简报、结构化/自由输入、相同或明确登记差异的图像条件、模型与种子、计时和预算按协议执行。作者真实做出的决定如实登记；若要测试界面而用了软件夹具，单列为软件走查。[作者预试与主持人记录](../../advisor-20261118/pilot-bridge/README.md)
3. 预试确定通路、容差、失败处理与盲评口径后安排外部配对操作及匿名评图。对构型、部件和感知指标分别设定分母，报告失败与不可判。原始评议者信息仅留在授权的研究存储中。[任务与验收](../../advisor-20261118/README.md)
4. 对照研究问题复核真实结果，再写第四、五章。可讨论的创新是从使用状态下的需求、设计者选择的部件/比例、模型实发输入、实际造型变化到观察者判断，能定位一次偏差发生在哪一段，以及换构型后的边界。文献支持方法选择；研究结论由本项目的输出和独立判断给出。

## 在另一台电脑复核研究材料

从仓库根目录运行下列命令。使用 Git、Node.js 22+、Python 3.10+ 和 Pillow；此轮实测为 Node 24.13、Python 3.11.9 和 Pillow 11.2.1。桥接程序使用临时 SQLite 和软件对照图。两个检查均可在没有模型账户的环境下完成。

~~~sh
node planning/advisor-20261118/semantic/lookup/check.mjs prototypes/drone-configurator/src/data/evidenceCards.json
python -B planning/advisor-20261118/pilot-bridge/check_controls.py prototypes/drone-configurator
~~~

第一项从 Git 的 HEAD 读取公开规范卡表，同当前前端卡表逐项比较，覆盖 36 张卡、35 个来源和 17 个话题。稀疏克隆需要先取得 `evidence/semantic-cards/cards.csv` 对应的 Git 对象。第二项读取旧工作台留存的真实导出，10 份中 2 份符合这套作者双条件预试的输入约束，随后跑通 27 项软件控制。三次合成候选出现对应两幅不同画面，盲判包按相同画面去重，来源表保留三次出现；新增真实模型调用与作者场次均为 0。

若使用 GitHub 下载的源码 ZIP，单次公开查询可以显式指定 JSON，使用下面这条命令核到 E009 和 E008。完整的规范卡对照仍需 Git 克隆。

~~~sh
node planning/advisor-20261118/semantic/lookup/cli.mjs --cards prototypes/drone-configurator/src/data/evidenceCards.json --task consumer_camera --layout quad --topic bag_fit --state folded
~~~
