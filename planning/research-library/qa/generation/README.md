# 一次折叠收纳查询的两次本地生成

使用同一个已冻结的[检索包](folded-bag.packet.json)。请求来自消费航拍、四旋、折叠状态和包内收纳话题。E009 是例证，E008 的型号与折叠描述冲突，作为限制材料共同返回。以下为本机 CPU 上的两次真实文字推断，固定 Qwen2.5-0.5B-Instruct 权重，贪心解码。两次均没有参与者、图像生成或自动参数更新。

| 运行 | 条件和实际观察 | 引用与主张审查 |
|---|---|---|
| [首次](initial-draft.json) | 模型收到任务字段、卡号、短引、适用范围与角色。它把“折叠后可以放入背包”写成“可以折叠成一个小型的背包” | 无卡号引用；对象和容器关系颠倒。草稿无效 |
| [修订提示后](revised-draft.json) | 显式加入每张卡的对象，并提示依据对象与上下文辨认原句指代。返回文本接近资料卡标题，夹有另一型号的说明 | 仍无卡号引用。程序保存失败状态，返回可回看的来源卡。文本未采作设计建议 |

两份回执均保留实际输入的摘要、权重摘要、包摘要、生成设置和原始回复。首次和修订后的提示条件不同。这是同一问题的工程诊断，既不能估计生成质量，也不能据此判断其他模型。带有效卡号的回复仍需逐句核原话是否足以支持其主张。当前可依赖的界面行为是展示原卡、反例与来源，生成草稿只供核对。
