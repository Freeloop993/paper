# 语料来源、检索与独立标注

研究者在准备需求证据时，可以从大量历史文本找回待核候选。设计者在工作台中检索时，使用已核过原话、来源和适用限制的公开卡。两种使用方式通过卡号和来源关系连接。设计参数的选定、回图量测和视觉评议另有各自的证据。

## 语料从哪里来

2026 年 11 月 18 日重新读取了原始工作簿、正式结案台账、证据池、短引卡和旧知识库文件。下表各行是不同层级；同一段话可以在多行出现。文件指纹及机器复算值见[导入报告](coverage.json)。

| 层级 | 本次实查 | 库里保存或连接的对象 |
|---|---|---|
| 采集与合并 | 6 份京东、淘宝／天猫评论工作簿有 11,241 条非空记录行。历史合并表有 8,755 条记录 | 私库的 `merged` 收匿名记录键与文本；原工作簿留在源目录。两张选定公开卡 E001、E008 的短引分别只在一个原始评论单元格出现 |
| 正式去重和筛选 | 7,443 个非默认文本簇；1,318 个簇带消费航拍机商品标题范围，228 个 A 类簇全部在此范围 | `cluster` 保存正文、历史决策、消费范围标记，按正式台账连接到 8,037 条不同合并记录。人工抽检进度沿用原台账。频数的单位是文本簇 |

历史片段与正式台账只去首尾空白时，109 个正式簇有唯一文本匹配候选，其中 A 类 1 个。采用 NFKC 归一化并去除空白后，3,486 个旧评论组匹配到 3,480 个正式簇，其中 A 类 109 个。两种结果分别进入 `legacy_match`；具体商品、操作状态与观察视角仍需补核。短引卡中的语义约束可以明确适用场景。整机小尺度、通用携带、折叠收纳和口袋／小包适配在 228 个保留簇内分别出现 99、67、12、4 次，同簇可以跨主题。

## 在另一台电脑使用

公开工作台检索使用仓库已有的 36 卡、35 个来源和 17 个话题。运行以下命令只需 Git 和 Node.js 22 或以上。在仓库根目录设置 `CORPUS_DIR` 为本页所在目录后执行。PowerShell 用 `$env:CORPUS_DIR` 取值；也可直接用实际相对路径替换示例中的变量。

```sh
node planning/advisor-20261118/semantic/lookup/cli.mjs --cards prototypes/drone-configurator/src/data/evidenceCards.json --task consumer_camera --layout quad --topic bag_fit --state folded
node "$CORPUS_DIR/evaluate_semantics.mjs" .
```

研究者如有获准使用的原件，可在本地建立 SQLite 资料库。需要 Python 3.10 或以上、包含 FTS5 的 SQLite。下列变量均由研究者在自己的设备上设置。 `PRIVATE_SOURCE` 指向含有 `补充调研_2026-10-09` 的目录，`LEGACY_JSON` 指向旧输入 `design_filtered_comments.json`，`PRIVATE_DB` 是公开仓库以外的本地输出文件。省略 `--legacy` 可仅导入正式材料。程序按事务生成临时库，完整性检查通过后原子替换同类型旧库。查询默认只打印匿名定位键。

```sh
python -B "$CORPUS_DIR/private_corpus.py" build --source "$PRIVATE_SOURCE" --cards prototypes/drone-configurator/src/data/evidenceCards.json --legacy "$LEGACY_JSON" --db "$PRIVATE_DB"
python -B "$CORPUS_DIR/private_corpus.py" query --db "$PRIVATE_DB" --collection cluster --text "折叠收纳" --limit 5
python -B "$CORPUS_DIR/private_corpus.py" query --db "$PRIVATE_DB" --collection legacy --text "保护罩" --limit 5
```

私有原件的最小输入为源目录中 `02-*.jsonl`、`64-*/06-*.json`、`63-*/01-*.json` 和 `63-*/04-*.json`，以及可选的旧输入。原始工作簿只在复核原始行数时使用。已获准使用同一数据的第二台电脑可以传输上述原件，或在受限的研究者渠道传输已建私库；两台设备对照输入文件摘要。本库含完整私人文本，工作台接口只取公开卡。公开仓库内的代码和短引可以独立使用。

默认私库查询在 A 类簇内按中文双字词项、拉丁词项检索及 BM25 排序。单个汉字使用字面包含检索；`--all-stages` 可查看其他筛查决策。限定 `merged`、`pool`、`legacy` 时分别在其独立数据范围内检索。研究者在本机使用 `--show-text` 可回看原话；旧片段的排名用于定位待核来源。公开设计环节从已审核卡取回原句、限制、同源反例和证据编号，随后由设计者确认话题和使用状态。

## 已测试的题与尚待实施的评价

[18 个开发控制题](development-probes.jsonl)逐项登记自然语言任务、研究者给定的结构化字段、预期动作和允许出现的卡号。实跑 8 题取回依据、4 题要求澄清、6 题无直接依据，公开卡组、反例角色及参数零修改逐项检查通过。D02 要求小包可装与口袋受限两条短引来自同一来源。D03 同时检查未指名配件的限制。D15 的展开顶视目标可以作为研究假设，控制题要求直接用户依据为空。脚本检验的是**给定正确字段以后**的检索动作。自由输入解析、排名质量和真实设计任务用时分别测量。

下一轮可以做两项独立评价。

1. 固定 36 卡、查询版本与任务预算。请未参与规则开发的人编写新设计问题，分别覆盖有依据、含混、无证据和明确反例的情况。两位评定者在看系统输出前，分别登记可接受**来源组**、必须同时出现的限制及期望动作；分歧保留并裁决。让同一批原始问题分别经过字面／稀疏检索、字段过滤检索、待实现的增强生成条件，分别记录输入是否由人补足字段。计算有依据问题的来源 Recall@3、首三组中错误场景数、限制呈现率，另报澄清和拒答的混淆表。记录每项分子分母。增强生成另核输出主张能否落在所引卡的原话与限制内。
2. 扩充来源时，先从 A 类范围按原记录键、原卡关联、NFKC 统一后的完整正文排除重复。此次 228 个文本簇中有 217 组可供追加独立编码。按固定种子已实际抽出 18 份私有待标材料，判读列留空、对应表单列。原先的 393 来源池覆盖全部 228 个保留簇，因此这批材料代表“与现有公开卡错开，等待另行编码”。要检验对全新来源的外推，还需另采来源并在建库前冻结划分。建库者不参与独立编码；相同来源或近似复述在裁决时一并登记。

```sh
python -B "$CORPUS_DIR/prepare_annotation.py" --db "$PRIVATE_DB" --out "$NEW_PRIVATE_PACKET" --count 18 --seed source-coding-20261118-v1
```

第二项输出 `coding.tsv` 和研究者单独保管的 `researcher-key.tsv`。面向编码者的列包括对象、观察状态、可支持的造型主张、限制、决定和编码者编号。两项评价截至本次交付均有 0 份独立新标注。数据源回读另可使用仓库既有的 `planning/advisor-20261118/semantic/verify_semantics.py`，指定 `--private-source` 时需 openpyxl。
