# P2 规格卡试跑：MiniMax H3-Image

**状态：** 2026-11-13，出图前登记。作者当天授权：用 MiniMax 直接跑，图通过本页标准后再开 GPU。开发调参，不进论文分母。

## 1. 这一批回答什么

只回答一件事：[三张规格卡草案](../../docs/protocols/e3-spec-cards-draft.md)编译出的请求，能不能出三个可辨的四旋设计方向，并且每张图的四个目标部位都按卡上写的做出来。

它不回答 W/L、d/D 的响应（E1 已做），也不代替作者选稿（E3）和独立评议（E5）。

## 2. 每次发什么

- 文字：规格卡第 4 节的固定开头、该卡的四句部位短语、固定结尾，再加一句参考图说明。逐字内容在 `run_p2.py`，脚本会断言它与规格卡草案一致。
- 参考图：一张骨架图，只画四条机臂和四个电机座，W/L = 1.00，浅色底。
- 接口：`/v1/images/edits`，`MiniMax-H3-Image`，1024²，PNG。该接口总会改写提示词，实际使用的文字记在响应的 `revised_prompt` 里。没有种子。
- 每张卡 3 张，一轮 9 张。

## 3. 通过标准（出图前写死）

**逐图七项，全部成立才算这张图合格。**

| 项 | 判什么 |
|---|---|
| S1 | 四个电机轴心都能定位 |
| S2 | 每轴两片桨叶，两侧长度相差不超过约 15% |
| S3 | 能判断哪一端是机头 |
| S4 | 没有参考图的线、块、点或文字残留 |
| S5 | 顶面没有朝向观察者的镜片 |
| G | 四个轴心读出的 W/L 在 1.00 ± 0.10 以内 |
| P | 该卡的“顶视判断标准”成立（卡 A、B、C 各一句，见规格卡） |

**整轮通过要同时满足两条。**

1. 每张卡的 3 张里至少 2 张合格。
2. 盲读者把 9 张图归到三张卡时，至少 7 张归对。

**谁来读。** 一名不知道条件的 AI 读者：只拿到打乱编号、重新编码的 9 张图和三张卡的文字，逐图填七项并归卡。通过与否以盲读者为准。Claude 知道条件的读数并列记录，只用来决定下一轮改什么。两者都不是真人读者，不计入论文的读者分母。

## 4. 不通过时怎么办

- 下一轮只改一处，并在 `run_p2.py` 的 `ROUNDS` 里写明改了什么、为什么。
- 可改的东西依次是：参考图的画法、参考图说明、某张卡的部位短语。卡的语义目标和四个部位不改，那是作者的决定。
- 每轮 9 张全部重跑，不挑图，不单补某一张。
- 最多 4 轮（36 张）。4 轮仍不通过就停，报告卡在哪一项。
- 通过后停下来给作者看图。作者认可之前不开 GPU。

## 5. 运行

```sh
export MINIMAX_API_KEY=...
python -B experiments/p2-spec-cards/run_p2.py --round R1 --dry-run
python -B experiments/p2-spec-cards/run_p2.py --round R1
python -B experiments/p2-spec-cards/run_p2.py --round R1 --sheet
python -B experiments/p2-spec-cards/run_p2.py --round R1 --blind DIR
```

结果在 `evidence/p2-spec-cards/`。

## 6. 边界

规格卡是草案，作者还没有确认。这里的“通过”只说明请求能把卡上写的东西做出来，不说明方案好看、值得深化，那要作者选稿和独立评议来判断。换到 Qwen 后是否仍然成立要另测。
