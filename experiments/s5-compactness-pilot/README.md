# 紧凑感评议包（S5 预试）

发给评议者的只有一个文件：[participant/无人机外观评议.html](participant/无人机外观评议.html)（1.2 MB，离线运行，不联网）。现行版本 1.1：图已换成 MiniMax H3 生成的产品渲染，原因见[评议用图的审查与更换](stimulus-review.md)。评议者打开它，看图作答，最后把结果发回。大约 10 到 15 分钟。

它回答一个问题：同一架四旋翼只改一个布局比例，不知情的人会不会觉得紧凑感变了，往哪边变。这是“用户说的紧凑”和“能控制的比例”之间还缺的那一步。读法和限度见[方案](protocol.md)。

## 怎么发

1. 找没有参与过这个设计、也没看过这些图的人。设计背景有无都可以，页面会问。
2. 把 `无人机外观评议.html` 这个文件发给对方（微信、邮件都行）。建议对方用电脑上的 Chrome、Edge 或 Safari 打开。
3. 对方做完后有两种交回方式：点“下载结果文件”把 JSON 文件发回；或者点“复制结果”，把一长串文字粘贴到聊天里发回。
4. 不要告诉对方研究想验证什么，也不要告诉哪张图是哪一档。

可以直接用的邀请语：

> 想请你帮忙做一个 10 分钟左右的小评议，是我学位论文的一部分。附件是一个网页文件，用电脑浏览器打开就行，不用联网。里面是一些无人机的图，按你自己的感觉回答，没有对错，做的时候不要和别人商量。最后页面会给出一份结果，下载文件发回给我，或者点“复制结果”把文字粘贴给我都可以。结果里没有你的姓名和联系方式。谢谢！

## 收回之后

把收到的文件放在本机的一个文件夹里（粘贴回来的文字每份存成一个 `.txt`）。答卷原件含自由文字，不要提交到仓库。

```sh
python3 summarize.py 回件/*
```

输出是一页汇总：评议者背景分布、核对题、两个比例各自的成对选择计数和逐人方向、三个词对在各档的单图评分。同一个编号重复发回的只算一份。

## 这个包现在的状态

- 软件走查通过：`node qa/walkthrough.mjs` 用三个合成评议者把页面从头做到尾（一个用手机宽度），另随机生成 300 份空白答卷检查题目排布，共 28 项检查，覆盖必答拦截、刷新后接着答、重复题排在原题之后且左右对调、下载与复制结果一致、页面无脚本错误；汇总脚本读回了预设的方向。1.0 版里重复题偶尔会排到原题之前，1.1 版已修正。
- 没有真人答卷。合成答卷不是研究数据，没有留在仓库里。
- 手机上只在浏览器的手机宽度下检查过排版。聊天软件里直接点开附件能不能正常作答没有测过，所以建议用电脑。
- 1.0 版（E1 图）在发出前撤回，没有人作答。1.1 版只换了图，读法沿用作者 2026-11-19 确认的文字，摘要记在 [freeze.json](freeze.json)。作者看过新图认可后即可发放。

## 文件

| 文件 | 用途 |
| --- | --- |
| `participant/无人机外观评议.html` | 发给评议者 |
| `protocol.md` | 材料、流程、读法、限度 |
| `researcher-key.json` | 匿名图号对应的比例档位和原图。研究者自留，不发 |
| `freeze.json` | 冻结时方案、页面和核对键的 SHA-256 |
| `summarize.py` | 汇总回件 |
| `stimulus-review.md` | 评议用图的标准、旧图为什么撤下、新图怎样做 |
| `h3/` | H3 出图脚本、8 次调用的实发参数与回执、派生脚本和逐图几何 |
| `build.py`、`template.html` | 重新制包（先在 `h3/` 下运行 `derive.py`） |
| `qa/walkthrough.mjs` | 软件走查 |
