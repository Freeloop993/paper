# P1 参数化提示词：回到作者原来的思路（2026-11-13，Claude 实现）

**状态：** 0 次生成。在 MiniMax H3-Image 上先把提示词和参考图调到作者认可，再开 GPU 移植到 Qwen。本批是开发调参，不进论文分母。

## 1. 为什么改

作者 11/13 指出：L1、D2 的参考图、提示词和出图都不行，不如一年前的水平；早期做法是从构型、角度、尺寸等参数入手，写得具体。作者给出的早期提示词见 `param_prompt.py` 的 `AUTHOR_PROMPT`。

对照之后，问题出在我这边：

1. **我把“参数化”收窄成了两个比例。** 作者配置器的参数覆盖构型、造型、结构、材质、配色、细节部件；我只留下 W/L 与 d/D，其余全部删掉或写成固定句子。
2. **我把参数短语换成了长句说明。** E1、L1 的提示词没有任何造型、材质、部件参数，D2 的 v2 又加了大段相机与材质说明。结果图要么平涂，要么是千篇一律的现成机型。
3. **我否定了作者的参考图画法。** 配置器的“轴心点加机臂线”被我换成桨叶剪影，后来又改成细线图接 Canny。
4. **我用“中性提示词”做参数实验的理由不成立。** 提示词在各档位间逐字相同就不会混淆，不需要把它写得没有内容。

E0、E1、L1 的数据保留：它们说明布局可以由条件图控制，但不是本文方法的出图。

## 2. 现在的做法

**参数 → 提示词。** `param_prompt.py` 按作者原句的结构编译：画质与媒介；构型（布局名、对角轴距、横纵跨度比、机臂角）；造型（机身风格、曲率半径、棱边角、机臂形式）；材质（机架、桨、格栅）；配色（色系、灯带）；细节部件；视角与光照。基线预设编译出来与作者原提示词逐字符相同，脚本里有断言。其余每条提示词都是这句话改动若干参数，图与图的差别可以追到具体参数。

**参数 → 布局图。** `build_diagrams.py` 画配置器式布局图：黑底、中心到四个轴心的蓝线、轴心红点，去掉了文字、坐标轴和比例尺（早期成图里的乱码和白线来自这些标注）。轴心坐标与 L1 条件图同源。

**机臂角与跨度比是同一个量。** 机臂角 = arctan(W/L)：1:1 对应 45°，0.7:1 对应 35°，1.3:1 对应 52°。提示词里两者一起写，布局图按同一个值画。

**词对落到参数上。** 两个设计方向预设：A（紧凑、整体、简洁、低调）和 B（舒展、分件、繁复、醒目），各自同时改动多项参数。词对 v1 由此进入生成。

## 3. 试验矩阵（13 张）

| 组 | 格 | 看什么 |
|---|---|---|
| T1 | 作者原提示词，关闭与开启服务端的提示词改写，各 1 张 | 能否复现早期那种质感；改写是否把参数改掉（响应里有 `revised_prompt`） |
| T2 | 设计方向 A、B | 多项参数一起变，外形和质感是否明显不同 |
| T3 | 每次只改一类参数：跨度比 0.7、1.3；机身切面、方正；白色、橙色点缀 | 哪些参数模型有响应，哪些没有 |
| T4 | 同一句话加布局图作参考，跨度比 0.7、1.0、1.3 | 电机是否落在红点上；有没有把蓝线红点画进图里 |

T3 的结果决定参数表里哪些参数保留。没有可见作用的参数（例如“8K”、相对机身过大的曲率半径）照实记录，不为好看而留。

## 4. 运行

```sh
export MINIMAX_API_KEY=...     # 只放环境变量，不写进仓库的任何文件
python -B experiments/p1-param-prompt/build_diagrams.py
python -B experiments/p1-param-prompt/run_minimax.py --dry-run     # 只打印请求
python -B experiments/p1-param-prompt/run_minimax.py               # 13 次调用
python -B experiments/p1-param-prompt/run_minimax.py --sheet       # 对照表
```

每格保存原图、请求（参考图只记文件名与摘要）、响应（含 `revised_prompt` 与用量）。已有图的格子会跳过；失败不自动重试，因为调用计费且不幂等。接口没有种子参数，同一请求再跑结果不同，记为该后端的限制。纯文字格用 `/v1/images/generations`，带布局图的格用 `/v1/images/edits`；模型名 `MiniMax-H3-Image`，1024²，PNG。

**我没能在线验证这份脚本。** 本会话的云端沙箱按网络策略拒绝连接 `api.minimax.io`，改用作者电脑的请求也被会话的安全策略拒绝。字段是照官方文档写的，`--dry-run` 通过；第一次真实调用若返回 400，请把响应原文贴到 #19，不要猜着改字段。
