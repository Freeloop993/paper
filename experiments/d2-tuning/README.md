# D2 开发调参批：提示词、控制窗口与两段式（2026-11-13，Claude 实现）

**状态：** 0 次生成。本批是**开发调参**，不是正式实验：结果只用来选定提示词和控制设置，不进论文的任何分母，不做盲读，由作者和 Claude 直接看对照表判断。选定之后再做一批有盲读的确认实验，那一批才是正文证据。运行须作者在 #3 授权 42 张。

## 1. 对 L1 的 A、B、C 与四张闭源图的判读

以下是我本人的知情看图，不算读数。我在 12 张原图上叠了目标轴心（红圈）逐张核对。

| 条件 | 轴心是否落在目标上 | 画面 | 结论 |
|---|---|---|---|
| A 方向线，全程控制 | 4 张里 2 张落上；另 2 张把黑色 X 和小圈**原样印在图上**，电机画在别处 | 落上的 2 张是平涂 | 方向线在边缘控制下语义不稳定：模型有时把它当机臂，有时当要照抄的图案 |
| B 另加桨叶轮廓，全程控制 | 4/4 落上 | 4/4 平涂，X 线贯穿机身 | 桨叶轮廓让模型认出“这里是旋翼”；平涂不是桨叶轮廓造成的（A 落上的两张同样平涂），是全程边缘控制造成的 |
| C 方向线，只控制前 35%，CFG 3 | 4 张里 3 张没落上，整机比条件图大一圈；读回的 W/L 约 1.0—1.2，不随 0.70、1.30 变化 | 有体积、像产品，但通体一种灰，无光泽差别，偏糊；2 张残留灰线 | 放开控制就有造型，但方向线锚不住电机 |
| 内置 GPT，布局图作参考（4 张） | 方向对、数值不准：目标 0.70 读回约 0.99、0.85；目标 1.30 读回约 1.67、1.72 | 材质分区、臂根体积、投影都有 | 闭源同样不精确；相机画在上端但镜头正对观察者 |

合起来：**能锚住电机的只有“带桨叶的部件图”；能出造型的只有“不控制或只在前段控制”。** 这两件事还没有在同一组设置里试过——带桨叶的条件图加短控制窗口。我上一轮把正好检验这一点的 R1 搁置了，是判断失误。本批 K 臂补上。

## 2. 已确认的问题与对应处理

| 问题 | 证据 | 处理 |
|---|---|---|
| 条件图的线被印进成图 | A 两张、B 四张、C 两张 | 条件图不再画贯穿中心的线；K 臂的主条件图只有桨叶与轴圈 |
| 电机不在目标位置 | A 两张、C 三张 | 用带桨叶的条件图锚定；K 臂扫强度与窗口 |
| 没有材质感 | C 四张通体哑光灰 | 旧提示词写的就是“matte neutral gray shell”，没有任何材质分区；换成 v2 简报（材质、光照、投影）。P 臂在不接控制的情况下单独检验提示词 |
| 相机在下端，与“front up”不符 | C 4/4 | P 臂同时试机头朝上与朝下，看模型听哪一种 |
| 镜头正对观察者 | 闭源 4/4 | v2 写明前向云台在机鼻下方、顶视只露外壳上沿、镜头朝前；负向词加“lens facing the viewer” |
| 千篇一律，像现成产品 | C 与闭源图都收敛到同一种外形 | 旧提示词没有任何造型语言。P4、P5 各加一句造型方向，看模型是否响应。这是词对进入生成（E3）的前提 |
| 每张 2—9 分钟 | L1 回执：126—519 秒，`cached_nodes` 每次为空；旧机 35 秒 | 见第 5 节 |

对 Codex 相机替换稿的意见：区分“相机在哪一端”和“镜头朝哪”是对的，物理描述我采纳并压缩成一句（见 `compile.py` 的 `V2`）。判读用语相应改为两题：“能否看出机头在哪一端”；“是否出现正对观察者的镜头”（出现记缺陷）。相机被机鼻遮住记“此视图不可见”，不算失败。正式读数表在确认批冻结时再改，L1 的表不动。

## 4. 运行

```sh
python -B experiments/d2-tuning/build_guides.py
python -B experiments/d2-tuning/compile.py     # 42 requests; manifest digest 714dd8fde416…35ac8
# 按 manifest 顺序提交：先 P，再 K，再 I
```

`compile.py` 以 E1 两份已运行的请求为模板，只改提示词、负向词、条件图文件名、强度、区间、种子、CFG、前缀；I 臂另加 LoadImage 与 VAEEncode 两个节点。K 臂用到三处条件图：本目录 `guides/`、`prototypes/drone-configurator/public/research-guides/`、`experiments/l1-layout/guides/`，请一并放进服务器 input。I 臂的父图命名同 L1 的 G。

`contact_sheet.py` 出三张对照表，K、I 两张在每幅图上画出目标轴心红圈。请把三张表和全部原图入库到 `evidence/d2-tuning/`，标明“开发调参，非正式”。

## 5. 先把速度修好

L1 每张 126—519 秒，回执里 `cached_nodes` 每次都是空的，说明每次提交都在重新读入约 40 GB 权重。旧机同一工作流 35 秒。请 Codex 在跑 D2 之前：

1. 查 ComfyUI 的启动参数与日志，确认时间花在读权重还是采样；若启用了 `--cache-none` 或每次提交前清空了模型，请去掉。
2. 允许加载器与文本编码节点命中缓存。这不影响结果：种子不同，采样器不会命中缓存；仍可在回执里核对 KSampler 确实执行。
3. 相同提示词的请求连续提交（manifest 已按此排序）。

把修正前后的单张耗时贴到 #19。目标是单张 1 分钟左右，42 张在一小时内跑完。修不动也照跑，只是报告原因。

## 6. 怎么判断，之后做什么

作者和我看三张对照表，回答四个问题：

1. P 臂：v2 是否比旧提示词有材质感；机头朝上还是朝下模型更听话；P4 与 P5 的外形是否明显不同。
2. K 臂：哪些格子红圈落在电机上，且两档的布局明显不同；其中哪一格最像 P2 的质感。
3. I 臂：重绘后是否还守得住轴心，是否摆脱了平涂。
4. 有没有残留的线或圈。

选出“提示词 + 条件图 + 强度 + 窗口”（或两段式）后，我冻结一批确认实验：W/L 三档 × 4 个种子，同提示词的纯文字对照，盲读点位与产品感。那一批替代 E1 成为正文的参数响应证据；E1 保留为“带桨叶轮廓、全程控制”的对照。

若 K、I 与 L1 的 D—G 都做不到，我会如实报告开源通路在这个任务上的边界，并提出把闭源模型用作第二段渲染的方案，由作者决定。
