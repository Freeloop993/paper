# 论文正文写作规范

所有写入 `src/` 的正文都按本规范写；改写旧稿时同样适用。2026-11-15 作者指出旧稿混有大量“实验登记”口吻后建立。

论文为南京航空航天大学机电学院工业设计工程专业硕士学位论文《人智协同驱动的多旋翼无人机造型参数化可控生成方法研究》。作者是设计者本人，导师审阅。

**问题。** 现稿的内容和数据基本正确，但大量句子是“实验登记／项目管理”的口吻，不像学位论文。导师读到会觉得是工作日志。作者举的例子是：

> 本文不训练 LoRA，这一调整已征得导师同意。软件验收、模型生成、设计者选择与独立评议分别计数。

前一句拿“导师同意”当理由，属于行政沟通；后一句是内部记账规则，读者看不懂它在论证什么。

**要求。** 在不改变事实的前提下，正文写成规范、通顺、论证清楚的学术中文。

## 一、必须保留，不得改动

1. **事实与数据。** 所有数字、比例、κ 值、样本量、档位名、实验编号（E0—E6）、模型与方法名称都保留。不得新增文中没有的事实、数据或结论。
2. **标记语法。**
   - 标题行（`#`、`##`、`###`）的文字不改，它们来自已审定的目录。
   - 引用 `[@键]` 原样保留，不增删。
   - 图行 `图：图X.X 标题 | 路径` 与表题行 `表：表X.X 标题`，只可润色标题文字，编号和路径不动。
   - 表格的行数、列数不变，单元格文字可以润色。
   - `注：` 行保持为注。
   - 整段的待补占位（以〔开头、以〕结尾的段落）原样保留，不改一个字。
   - 文件开头的 `<!-- … -->` 编辑备注不进 Word，可以保留。
3. **限定与边界。** 结论的限定条件（只限正交顶视、只限所测条件、AI 判读不能替代真人等）要保留，但用学术的说法写，同一限定不要在一段里反复强调。

## 二、必须删去或改写

1. **行政与沟通。** 删去“征得导师同意”“作者确认”“作者授权”“在 #3 记录”“作者答”“按作者要求”等。若某项取舍需要说明，给出学术理由。例如不训练 LoRA，应说明原因：样本量小、研究重点在可检查的参数与修订，风格一致性改由父图参考与描述性评议考察。
2. **协作与工具链细节。** 删去 Codex、Claude、AI 助手、GitHub、仓库、提交、工单、回执、调度程序、服务器、打包、元数据、文件名、哈希值、SHA-256、具体日期与钟点。生成环境只需写清模型、工作流框架与采样设置，例如 Qwen-Image 2.1、ComfyUI、步数。
3. **记账式用语。**
   - “分母”“不进入分母”“计入分母”改为“统计基数”“不计入统计”“计入统计”。
   - “分别计数”要写清是哪几类结果分开统计，以及为什么分开。
   - “出图”“跑”改为“生成”“运行”。
   - “登记”“出图前登记”改为“预先设定”“在生成前确定”。
   - “实收”“回收”“核验”删去，或改为“生成”“记录”。
4. **内部代号。** 不出现内部批次代号，如 S12、S16、WLQ、REV1、REV2B、E2R、HEXA3、P2，改为描述性说法，例如“造型响应实验”“修订二的开发验证”。E0—E6 在表 1.2 中已定义，可以继续使用。
5. **口语和英文夹杂。** 正文中不夹英文口语。引用设计者的话时，若原话夹英文或过于口语，改为转述，例如“设计者更倾向于相机装在下端的方案”。表格中“摘录原话”一列可保留原话，但须去掉粗俗词。
6. **随机种子。** 种子号可保留在表格中供复现；正文叙述只说“相同随机种子”，不罗列种子号。
7. **流程失误。** 不写调度停机、文件混入等工具故障。转译偏差这类方法上的问题可以写，应写成“转译偏差”及其对方法的启示，不写成检讨。

## 三、统一术语（各章一致）

| 现稿说法 | 改写为 | 说明 |
|---|---|---|
| 知条件 AI 初读、知条件读数、知条件查看 | 知情判读 | 判读者知道生成条件。只作参考，不作正式结果 |
| 盲读、盲态读数、两次隔离的 AI 盲读 | 盲态判读；两个相互独立的 AI 判读会话 | 判读者不知道生成条件 |
| 揭盲 | 判读完成后再与生成条件对照 | |
| AI 读者 | AI 判读者 | 以多模态大模型按判读表逐项判读 |
| 开发门、开发判据 | 开发阶段的通过标准 | |
| 开发图 | 开发样图 | 不作为设计候选 |
| 正式批 | 正式实验 | |
| 开发彩排 | 开发阶段试验 | |
| 父图编辑 | 以父图为起点的编辑 | |
| 按档位重出、点线图重出 | 按新档位重新生成 | |
| 档位 | 档位 | 保留，第 3 章已定义 |
| 造型响应批 | 造型响应实验 | |
| 设计者（作者） | 设计者 | 不写“作者” |

第 3 章（3.6 节）须对“知情判读”“盲态判读”“AI 判读者”给出定义，其他章节直接使用。

## 四、文风要求

1. **完整成段。** 用完整的学术句子组织段落，有论点、依据和小结，不写成清单式的短句堆叠。
2. **主语。** 少用“研究者”，多用“本文”“本研究”。设计者的决定写成“设计者选择……，理由是……”。
3. **限定语。** 同一段里限定语只说一次。删去“只作……不作……”式的重复叮嘱。
4. **结果与讨论。** 先陈述结果，再解释原因，最后说明对方法的意义。
5. **修饰与语气。** 不用夸张或情绪化的修饰词，不用“我们”。
6. **长度。** 篇幅可以因删去冗余而缩短，但方法、结果、局限这类实质内容不能删。

## 五、示例

**例 1。**
- 原稿：本文不训练 LoRA，这一调整已征得导师同意。软件验收、模型生成、设计者选择与独立评议分别计数。
- 改写：本文未对生成模型作 LoRA 微调。原因在于，本研究关注的是设计意图能否以可检查的参数进入生成、修订过程能否追溯，而小样本微调会把风格因素与参数响应混在一起，难以分别评价；风格一致性改由父图参考与描述性评议考察（3.5 节）。原型软件的功能验证、模型生成结果、设计者的选择与独立评议的判断属于不同性质的证据，本文分别统计、分别报告，不合并为单一指标。

**例 2。**
- 原稿：闭源图像接口只用于两处：后端对照实验（6 张）与条件选择阶段的开发彩排（见 4.1.3 节），二者都不进入正式效果的分母。
- 改写：闭源图像接口仅用于后端对照实验（6 张）与条件选择阶段的开发试验（4.1.3 节），其结果不计入正式实验的统计。

**例 3。**
- 原稿：从第一轮初稿开始生成（2026 年 11 月 14 日 23:24）到最后一次修订开发图完成（11 月 15 日 09:10），历时约 9 小时 46 分，其中包括夜间等待设计者回复，以及调度程序因打包文件混入系统元数据而停机的空转。
- 改写：E3 未逐步记录设计者的操作时间。从第一轮初稿生成到修订停止，历时约 10 小时，其中大部分为等待设计者评阅的时间，因此该时长反映的是研究流程的周转，不能代表设计者的工作量。

## 六、提交前检查

在本目录运行下面的命令。没有输出才算通过；有输出就逐条改掉。命令只查正文，`<!-- -->` 备注不算。

```sh
python3 - <<'PY'
import re, glob
BAN = ["征得","导师同意","作者确认","作者授权","Codex","Claude","GitHub","仓库","回执","工单","调度","元数据","SHA","哈希","分母","出图","登记","实收","知条件","揭盲","开发门","开发彩排","盲读","prefer","小测","锁稿"]
for f in sorted(glob.glob("src/*.md")):
    t = re.sub(r"<!--[\s\S]*?-->", "", open(f, encoding="utf-8").read()).replace("输出图", "")
    for w in BAN:
        if w in t: print(f, w)
PY
```
