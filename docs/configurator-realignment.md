# 找回参数配置器后的研究纠偏与 Claude 接手任务

作者希望回到一个具体的工业设计问题：设计师能否把使用任务转成可修改的部件与造型要求，让生成结果在保留指定结构关系的同时，给出有体积感、部件关系协调、值得继续深化的方案？原型要让设计者看见、选择和修订这些要求。准确定位四个电机只能回答其中的结构问题。

## 原型留下了哪些可以核对的证据

旧版把机架、动力、机身、起落架、配件交给设计师选择。轴距、机臂厚度、桨径、机身长宽高与云台开关都进入状态。新手、摄影和户外亲子三种画像影响描述。九段模板把选择展开为风格、部件与功能、布局与人机、配色、视觉语言、材料、标识、摄影呈现及最终提示词。作者先前展示的蓝橙亲子四旋就是这套模板能表达的简报。双层机身、亮橙桨尖等在源码中是示例，优化时把它们从共用默认要求中移开。旧画像与历史示例不构成本研究的参与者或正式刺激材料。[原型与源码地图](../prototypes/drone-configurator/README.md)

旧版有根据部件和用户画像检索评论的代码。本地 JSON 实核 5,614 个非空文本片段，含 3,603 个不同的非空 comment_id；人数、市场占比、与旧台账 7,443 个文本簇的对应关系均未核定。公开仓库保留读取逻辑及统计口径。论文第 3.2 节如需将评论用于简报，应能从去标识的证据卡追到作者采纳的需求；“便携”本身推不出具体毫米数。旧版优化建议也不等于作者已经采纳。[仓库现行状态与评论口径](../STATUS.md)

源码有两条容易混淆的路。配件面板会把优化内容写回可编辑附加文本，下次组装请求可携带它。主面板“预览优化结果”把结果存入展示状态，“生成图像”则从参数重新组装文字，可另走 Gemini 优化；旧主请求没有定位图或父图字段。画像面板的值也应在重构时检查，旧文本服务按带表情的键查找，可能落到通用描述。请保存设计者最后确认的文本、实际发送的文本和图片身份，三者有差异时让操作者看见。[配件面板](../prototypes/drone-configurator/src/components/Parameters/AccessoriesParameters.tsx) · [主界面](../prototypes/drone-configurator/src/App.tsx) · [实际请求](../prototypes/drone-configurator/src/services/imageGenerationService.ts)

## 已和作者对齐的设计决定

| 决定 | 落到原型与证据上 |
|---|---|
| 先确定任务、目标部位、想改变什么、想保留什么，再决定如何生成 | 四旋是日常随行航拍，主要看相机与机鼻整合、机臂到机身的过渡。六旋是农业植保，主要看药箱、喷洒部件与六臂机架的整合。按任务切换部件字段。旧巡检/测绘图保留原标签。 |
| 定位图只约束有理由锁住的结构 | 桌面原型可按轴距、跨度比或相邻夹角给出轴心位置并导出 PNG/JSON。默认给轮毂定位和必要连接关系，机壳外轮廓、曲面及接缝留给设计者和模型探索。此前八边形轮廓图把一种壳体形状写进了输入，现按作者决定整组归入历史档案，正式图表和评议不得复用。 |
| 量测与看造型各用合适的视图 | 用约定的俯视坐标和机头方向核对轴心、相邻夹角与跨度；无法辨认或方向未定就记未知。斜前上视产品图用于看相机嵌入、臂根厚薄和体积过渡。由模型单独生成的两张视图不能仅凭相似外观认作同一几何体。共同方案须记录父图、版本、对应部件，无法确认的关系保留未知。 |
| 提示词属于实验输入 | 统一任务、允许改变的参数和摄影条件，冻结实际发送文本、位置图、可选父图及变化项。研究 D 自由文字与 S 结构化规格时，两组使用同等级工具、相同的修改机会。若只有一组增加渲染或材料细节，结果就同时受两种变化影响。 |
| 参考图有具体身份 | 轴位定位图负责布局；被选中的父图用于指定方案的外观延续，是否采用及强度需单独记录。原版主按钮按文本请求图像；当前参考图路线可使用支持图像输入的后端。GPT Image 与 Qwen/ComfyUI 按实际后端分别登记，参考图替代训练的路线按已有导师意见状态表述。 |
| 图有没有设计价值，另作判断 | 研究分别记录结构保持、任务部件是否可辨、整合和协调程度、修改采纳与操作代价。校准示意图可教人点轴心；评价相机或机臂整合需要看得见这些部件的产品图。细节不足按原协议记录不可判或筛选结果，保留原分母及正式反馈。 |

## Claude 的首个改动与验收

请从这个[可编辑原型](../prototypes/drone-configurator/README.md)开一个小 PR。原始意图以[功能需求](../prototypes/drone-configurator/original-design-brief.md)为参照，几何计算优先复用[桌面版实现与导出样例](../experiments/desktop-parameter-v2/README.md)，修订、停止和回选规则参看[既有离线改稿台](../experiments/operator-workbench/README.md)。原型首轮可以离线完成。

1. 让设计者选择任务，在同一页确认需求依据、目标部位、改变项、保持项和自由项。四旋示例可填“相机更融入机鼻，臂根过渡更连续；保留四轴布局，机壳曲面由设计者决定”。六旋入口应能表达药箱与喷洒部件。
2. 从同一份已确认规格构建定位图、轴心坐标、最终文本与可选父图引用。把确认后修改、重新预览、导出组织成一条路径。预览与实际导出的请求应一致。身份、版本和哈希可用于跨机器复核。
3. 离线演示同一个四旋初稿经历一次局部修改，保存前后规格、实际导出的请求、设计者选择与理由。另做一次六旋任务切换，核对部件和轴数。把结果标为软件验收。正式生成或人评沿用相应实验工单。
4. PR 附可重复的操作步骤、失败或未接的入口、构建结果。Claude 回 [#1](https://github.com/Freeloop993/paper/issues/1) 说明代码影响哪些章节，Codex 按 [#2](https://github.com/Freeloop993/paper/issues/2) 核对实际输入输出。只把本人实际完成的环节写进回执。

写作沿用[六章目录](../manuscript/outline.md)。第 3.2 节说明评论依据，第 3.3–3.5 节说明人工确认、布局条件和反馈，第 3.6 节区分结构、感知与代价。第 4 章题为“四旋翼无人机造型生成与方法应用”，4.1 可据源码说明实现，4.2–4.4 的方向筛选、迭代与深化仍需真实过程。第 5.5 节单列植保六旋适配。旧批的实图、失败、缓存、评议和模型身份各沿用原账；这个公开源码交接没有增加任何生成、人次或实验结论。
