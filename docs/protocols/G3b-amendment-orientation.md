## 1. 发现

对照 G3 的两张原件（[父图 S1-B1-T](../../evidence/s1-axis-repeat/originals/S1-B1-T.png)、[带父图改稿](../../evidence/g3-actual/originals/G3-with-reference.png)）：

- 父图画面**上端**已有一组深色部件（中央深色窗与两侧圆形件）。S1 复测把这张图的机头读为朝上，初测记为未知（[s1-axis-repeat](../../evidence/s1-axis-repeat/README.md)）。
- 带父图改稿与父图几乎逐处相同，唯一明显的变化是画面**下端**新增了一个镜头部件；上端那组深色部件原样保留。
- 修改文字写的是 “the front camera … the nose”，没有说明图中哪一端是机头。

以上是我本人看图的描述，属于**未封存、已知条件的非盲观察**，不计入任何读者分母。它与已入库的记录相符：真人评者“认出了画面下方新增的摄像头，并对机身另一端黑色部件的功能感到困惑”（[g3-actual](../../evidence/g3-actual/README.md)）。

## 2. 这改变了什么判断

1. **G3 的“改不动”说法需要收窄。** [G2d-G3b 规格](G2d-G3b-spec.md)第二节把 AI 读数概括为参考图可能“保得住、改不动”。更贴近原件的说法是：模型在保持其余部分的同时**做出了可见的局部改动**，但改动的形式是“在另一端新增一个相机”，不是“把已有前摄与机鼻融合”。AI 判“不可辨”与真人判“可辨”的分歧，至少部分可以由此解释；仅凭一份答卷不能确定。
2. **G3b 现有四个配置都继承了同一处歧义。** 四份请求都只写 front camera / nose。如果模型再次在下端加相机，按现表“相机嵌入机鼻、壳面收拢”一题，读者可能对着新增相机判“可辨”，而父图原有的前部部件并没有被修改。这样得到的“可用”配置，进入改稿台后并不能完成任务 A 所要的修改。
3. **这也是 D/S 正式采集的风险。** 任务 A 的检查问题是“能否指出视觉前端与相机”。顶视图里前后不明时，操作者写“前摄”，模型可能改另一端。场次记录须能区分“目标部位被修改”与“别处新增了部件”。

## 3. 建议的修订（均在出图前，请作者逐项确认）

**R1 判读表加两题（不改请求，建议必做）。** 在 G3b 观察题之后、目标题之前增加：

- 改稿中相机类部件各在画面哪一端（上／下／两端都有／看不清）；相对父图是新增、原位修改还是未变。
- 父图上端原有的深色部件在改稿中是保持、被修改还是消失。

目标题“相机嵌入机鼻、壳面收拢”的“可辨”须同时满足：改动发生在**父图原有的前部部件**上，或父图原有部件被合理替换且全图只有一处前摄。**仅在另一端新增相机，记“不可辨”，并在 observed_changes 中注明“新增部件”**。“可用”定义（保持 ≥2/3 且修改可辨）不变。

**R2 由作者指定这张父图的机头端（建议必做，属设计者决定）。** 助手不代定。作者看父图后在 #3 写明“上端为机头”或“下端为机头”或“父图前后不明”。若为“前后不明”，G3b 的结论须加限定：结果只说明前后不明的父图上的修订行为。

**R3 配置 i 的文字加朝向句（可选）。** 配置 i 本来就是改写后的结构化指令，不承担与 G3 原文字的逐字对照。可在作者按 R2 指定后加一句指明机头在画面哪一端、要改的是该端已有的相机部件。ii—iv 保持“同 G3 原文字”不动，以保留与 G3 的可比性。加了这句后，i 与 G3 带父图条件的差别变为“结构化＋指明朝向”两处，须在结果里照此写，不能单独归因。若作者不想增加这一处差别，就只做 R1、R2。

**R4 G3 记录的表述（文字，不改数据）。** G3 README 与规格中“保得住、改不动”的概括，建议由 Codex 在 G3 README 追加一句原件描述：带父图改稿的可见变化位于画面下端的新增镜头部件，上端原有部件未变；此描述来自非盲看图，读者分母不变。
